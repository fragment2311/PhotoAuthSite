# Обновление из админки

На странице «Настройки» администратор видит установленный commit, доступное обновление и до 20 сообщений коммитов. Если версия содержит миграции, показываются имена файлов и отдельное предупреждение. До нажатия «Установить обновление» никаких файлов приложения и таблиц БД не меняют.

## Docker

1. В `.env.production` задайте `UPDATE_AGENT_TOKEN` случайной строкой минимум из 32 символов. Сгенерировать можно так:

   ```bash
   openssl rand -hex 32
   ```

2. Запустите Compose с профилем обновлений:

   ```bash
   docker compose --profile updates --env-file .env.production -f compose.yaml up -d --build
   ```

Агент доступен только во внутренней сети Compose и не публикует порт наружу. Только у агента есть Docker socket. Не переносите этот mount в сервис `app` и не запускайте `docker compose down -v`.

## Запуск без Docker

Приложение определяет режим по среде PHP: контейнер использует адрес `updater` внутри Compose, приложение на хосте обращается к локальному агенту `127.0.0.1:19100`. Если среда не определяется автоматически, задайте `UPDATE_RUNTIME=docker` или `UPDATE_RUNTIME=host`.

Для режима хоста установите отдельный агент ОС из корня проекта:

- Linux: `sudo bash install-update-agent-linux.sh /путь/к/PhotoAuthApp`. Установщик запрашивает имя службы systemd PHP-FPM/Apache и адрес проверки. Агент запускается от владельца каталога, слушает только loopback, а право перезапуска получает только для выбранной службы.
- Windows: запустите `Install-PhotoAuthUpdater.ps1` от администратора. Укажите папку проекта, файл окружения, IIS-пул либо службу Apache/XAMPP и адрес проверки. Агент запускается как задача SYSTEM при старте Windows и принимает запросы только с этого компьютера.

Установщик создаёт случайный токен при необходимости и сохраняет его в файле окружения, не задавая фиксированный путь проекта. Настройки агента и резервные копии схемы находятся вне Git-папки. Агенту нужны Git, PHP, Composer, Python 3.10+ и доступ к выбранному способу перезапуска. Apache/XAMPP в Windows должен быть зарегистрирован как служба; вручную запущенный процесс автоматически перезапустить нельзя.

При прямом запуске агент обновляет Git-папку, устанавливает зависимости Composer, сохраняет только структуру MySQL перед подтверждёнными миграциями, запускает миграции и перезапускает выбранную службу. `.env`, `storage` и записи БД не очищаются. Если агент ОС или способ перезапуска не настроен, обновление не запускается.

## Поведение

- Без миграций обновляется только контейнер `app`; MySQL, `.env.production` и именованные тома не удаляются.
- Перед подтверждёнными миграциями приложение останавливается, сохраняется только структура MySQL, затем запускаются миграции и проверяется `/login`.
- Снимок схемы не содержит записей. Подтверждённая миграция может изменить или удалить записи; автоматически восстановить их без копии данных нельзя.
- Если обновление без миграций не проходит проверку, агент возвращает прежний код; в Docker дополнительно возвращается прежний образ.
- При ошибке миграции агент пытается запустить приложение с обновлённым кодом, но не откатывает БД без копии строк. Если приложение доступно, блок обновления покажет ошибку; после ручной проверки и завершения нужного восстановления можно подтвердить восстановление. Эта кнопка только снимает блок агента и отмечает версию обработанной. Если приложение недоступно, сначала восстановите его на сервере.

Снимки схемы и состояние последнего задания хранятся в Docker-томе `update_agent_data` для Docker и вне Git-папки для агента ОС.
