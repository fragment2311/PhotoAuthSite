# Кнопка обновления PhotoAuthApp

## Цель и понимание

- В настройках администратора показывать текущую и доступную версии.
- До установки показывать список коммитов/изменений и миграций базы.
- Администратор может отменить установку; для миграций показывается отдельное предупреждение и подтверждение.
- Обновление пересобирает и перезапускает только контейнер приложения.
- `.env.production`, внешняя MySQL и постоянные Docker-тома остаются на месте.
- Полную копию строк БД не создавать. Перед подтверждёнными миграциями сохранять только схему БД.

## Предлагаемая архитектура

В Compose добавить изолированный сервис-обновлятор во внутренней сети приложения. Он единственный получает Docker socket и доступ на запись к checkout; веб-контейнер не получает Docker socket. Обновлятор предоставляет только фиксированные операции проверки, запуска, отмены и чтения статуса, защищённые отдельным случайным секретом. Не публиковать его порт наружу.

Laravel admin-страница вызывает обновлятор с серверной стороны. Маршруты ограничить существующими `Authenticate` и `role:Администратор`, операции изменения выполнять POST-запросами с CSRF-защитой. Одновременно может идти только одно обновление; браузер получает статус опросом.

Перед изменением кода проверять чистоту отслеживаемых файлов и fast-forward обновление `origin/main`. Список изменений строить по коммитам и файлам миграций между установленным и доступным commit SHA. Установка сохраняет предыдущий image tag и commit, собирает новый image и проверяет `/login`. При ошибке запуска вернуть прежний image и commit. Миграции без отдельного подтверждения не выполнять. Для подтверждённых миграций сначала сохранить только структуру БД; полный дамп данных не создавать.

## Надёжность и границы

- Обычное обновление не выполняет команд удаления томов и не меняет конфигурацию приложения.
- Резервная копия только схемы не восстанавливает строки данных. При подтверждённой миграции, которая удаляет/переписывает записи, сохранность этих записей не гарантируется без копии данных; предупреждение должно сообщать об этом до запуска.
- Обновление приостанавливается, если checkout изменён, нет связи с агентом/GitHub, не хватает места для сборки или health check не проходит.
- Значения секрета агента не добавлять в Git и не показывать в ответах/журналах.

## Журнал решений

| Решение | Причина |
| --- | --- |
| Статус доступности и список изменений рядом с кнопкой | Администратор заранее видит, что установится. |
| Агент отделён от веб-контейнера | Только выделенный компонент управляет Docker. |
| Подтверждение отдельно для миграций | Изменение схемы может повлиять на данные. |
| Копия только схемы, не строк БД | Полный дамп слишком велик; это ограничение показывается явно. |
| Пересобирать только сервис `app` и проверять health | Redis и постоянные тома остаются без изменений. |
