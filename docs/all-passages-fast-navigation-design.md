# Быстрая навигация «Все проходы»

## Задача

Страница «Все проходы» должна быстро открываться и применять фильтры при большом журнале. Пользователь должен сразу видеть, что поиск выполняется.

## Согласованные требования

- В выборку входят только проходы с заполненным `CameraPhoto`.
- Применяются существующие фильтры: строка поиска, период и тип прохода.
- Полное число найденных записей и номера страниц не показываются: их подсчёт не выполняется.
- Результат содержит до 60 фото.
- Навигация: «В начало», «Предыдущая», «Следующая», «В конец».
- «В начало» открывает самые новые, «В конец» — самые старые фото среди текущих фильтров.
- При открытии раздела из галереи и при запуске поиска немедленно показывается перекрытие «Идёт поиск фото…».
- Очередь, временные файлы и изменение фотоархива не требуются.

## Принятое решение

Использовать курсорную пагинацию по стабильному порядку `AccessTime`, `IdPassage`. Она не выполняет общий `COUNT(*)` и не использует медленное смещение `OFFSET` на глубоких страницах. Для перехода в конец применяется отдельная выборка в обратном порядке с теми же фильтрами.

## Ограничения и надёжность

Журнал проходов остаётся «живым»: новые записи, добавленные во время просмотра, могут попасть на соседнюю страницу. Вторичный порядок по `IdPassage` делает переходы однозначными и не допускает дублей из-за одинакового времени прохода.

## Журнал решений

| Решение | Альтернатива | Причина |
|---|---|---|
| Курсорная пагинация | Обычная пагинация с `COUNT(*)` | Исключает полный подсчёт и медленные глубокие страницы. |
| Крайние кнопки вместо номеров страниц | Номера и переход по странице | Позволяет быстро открыть новые или старые записи без знания общего числа страниц. |
| Мгновенное перекрытие | Задержка 0,5–1 с | Пользователь сразу понимает, что его действие принято. |
