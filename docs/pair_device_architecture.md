# Архитектура устройств точки

## Текущая схема

`pairdevices` описывает точку прохода: её название, локацию, комментарий и
активность. Состав устройств хранится в отдельной таблице
`PairDeviceDevices` (на используемом MySQL физическое имя отображается в
нижнем регистре).

Одна строка `PairDeviceDevices` — одно физическое устройство в одной точке:

- `IdPairDevice` — ссылка на `pairdevices.Id`;
- `IdController` или `IdCamera` — ссылка на контроллер либо камеру;
- `Role` — `controller`, `entry_camera` или `exit_camera`;
- `SortOrder`, `IsActive` — порядок ответа и активность связи.

`IdPairDeviceDevices` в `pairdevices` больше не используется. Прежняя
таблица сохранена как `PairDeviceDevicesLegacy_20260923` и не участвует в
работе приложения.

## Ограничения

- В строке указывается либо контроллер, либо камера.
- У точки может быть только один контроллер, одна камера для сохранения фото
  и одна дополнительная камера выхода.
- Одно физическое устройство нельзя назначить двум точкам.

Эти правила защищены ограничениями БД и дополнительно проверяются в форме
настроек сайта.

## Работа приложений

`GET /api/device-pairs/active?format=v2` возвращает `devices[]` с ролями из
таблицы. Для уже установленных клиентов сервер также отдаёт поля v1:
`controller`, `entry_camera`, `exit_camera`.

- SkudConsole использует `entry_camera` как основную камеру снимка и при
  необходимости может использовать `exit_camera`.
- SmartPass загружает состав точки из `devices[]` и распознаёт новые имена
  ролей.

Подробнее: [device-pairs-api.md](device-pairs-api.md).

## Настройки на сайте

В форме точки указываются контроллер, камера для сохранения фотографии и
необязательная камера выхода. При сохранении старые строки этой точки в
`PairDeviceDevices` заменяются её актуальным составом.

Существующие точки, созданные до перехода, нужно один раз открыть и сохранить
в этой форме: новая таблица после миграции преднамеренно не заполнялась
старыми неоднозначными связями.
