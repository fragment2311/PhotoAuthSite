# Финальный план с учетом существующей таблицы Logs

## 1. База данных

Используем уже существующую таблицу Logs из вашего скрина, без создания новой таблицы.

Поля таблицы:
- Id
- Message
- EventDate
- LogType
- StackTrace
- IPAddress

Решение:
- Не создавать таблицу error_logs
- Работать только с Logs
- Все ошибки писать в Logs

## 2. Правило доступа для других организаций

Если другим организациям нельзя менять настройки отчетов, то да — настройка должна быть только в коде и в конфиге на сервере.

Практически:
- убрать UI-настройки отправки отчетов для клиентских ролей
- доступ к просмотру логов оставить только администратору
- параметры отправки email/бота хранить в env и config

## 3. Логирование в таблицу Logs

Маппинг данных:
- уровень ошибки -> LogType
- текст ошибки -> Message
- stack trace -> StackTrace
- IP пользователя -> IPAddress
- дата/время -> EventDate (по умолчанию CURRENT_TIMESTAMP)

## 4. Отображение логов на сайте

Страница в админке должна уметь:
- фильтр по типу лога LogType
- фильтр по дате и времени EventDate (от/до)
- поиск по Message и StackTrace
- сортировка по EventDate desc
- пагинация

## 5. Email-уведомления

Канал email оставляем:
- получатель: access_line@bk.ru
- отправка только для error/critical/fatal
- warning только в БД и на экране логов

## 6. Бот (без MAX)

MAX не используем.

Если нужен бот, оставляем только один канал бота как опциональный драйвер, но базовый контур должен работать даже без него:
- запись в Logs обязательна
- отображение в админке обязательна
- email обязательна

## 7. Минимальный порядок внедрения

1) Создать модель для таблицы Logs (с текущими именами колонок)
2) Сделать сервис записи ошибок в Logs
3) Подключить отправку email после записи в Logs
4) Сделать админ-страницу логов с фильтрами и поиском
5) Ограничить доступ к странице ролями админа
6) Убрать/заблокировать UI-настройки отчетов для неадминов

## 8. Готовый критерий результата

Система считается готовой, если:
- каждая ошибка попадает в Logs
- лог виден в админке
- работают фильтры LogType + EventDate + поиск
- email уходит на access_line@bk.ru для error и выше
- у неадминов нет доступа к настройке отчетов
